# Core transcription
faster-whisper>=1.0.3
# PyAV 19.0.0 (2026-09-29) removed the `metadata_errors` argument of
# av.open(), which faster-whisper (<= 1.2.1) still passes when decoding
# audio. With av 19 every transcription fails with
# "open() got an unexpected keyword argument 'metadata_errors'" (seen on
# the macOS build's smoke test, 2026-09-30). faster-whisper only says
# av>=11, so pin it here until a faster-whisper release supports av 19.
av>=11,<19

# faster-whisper pins tokenizers only loosely (>=0.13,<1), so a build done
# today can bundle whatever tokenizers is newest on that day. The nvidia_asr
# optional feature (see core/optional_deps.py) installs 'transformers' ON
# DEMAND, later, into a separate user-writable dir that is APPENDED to
# sys.path — so this bundled tokenizers (prepended, always wins the import)
# is the one 'transformers' actually sees, not whatever on-demand pip
# resolves. If the two drift apart, 'transformers' refuses to import with
# "tokenizers>=X,<=Y is required ... but found tokenizers==Z". Pin here to
# stay inside whatever range the pinned transformers below (see
# core/optional_deps.py's nvidia_asr entry) declares — re-check both
# together (pip show transformers; python -c "from
# transformers.dependency_versions_table import deps; print(deps['tokenizers'])")
# before each release build and bump in lockstep if it no longer matches.
tokenizers>=0.22.0,<=0.23.0

numpy>=1.26,<3

# Live tab audio capture. Small, no heavy transitive deps (unlike the
# opt-in on-demand extras below), so — unlike those — these ship by
# default rather than going through core/optional_deps.py: the Live
# tab's default source is "Microphone", and a user should not have to
# find a console and run pip themselves to make the default option
# work. sounddevice is cross-platform; PyAudioWPatch is a WASAPI-
# loopback fork of PyAudio and only installs/works on Windows (the
# "System audio" source), hence the marker.
sounddevice>=0.4.6
PyAudioWPatch>=0.2.12.6; sys_platform == "win32"

# Word-level alignment refinement via stable-ts is NOT a base requirement

# (measured in a clean container) -- while the app already installs it on
# demand the first time "Refine word timings with stable-ts" is used

# deleted it after installing anyway, and the Mac installers filtered it

# Optional cloud Speech-to-Text backend (Google Gemini API): needs NO
# new dependency. It talks to the Gemini REST API with the stdlib
# urllib.request (no google-cloud-speech / google-generativeai). The
# user pastes a free API key from aistudio.google.com in
# Advanced > Backend. See docs/CLOUD_STT.md.

# REAL Google Cloud Speech-to-Text v2 backend
# (transcribe_backend="google_cloud_stt") is intentionally NOT listed here.
# It used to be pinned/bundled because a maintainer-owned service-account
# key shipped with the app and made this the DEFAULT engine, so paying the
# install weight up front removed the first-use wait. That key was revoked
# and its bundling permanently removed 2026-08-04 (see SECURITY.md,
# "Retired: the bundled Google Cloud key") — the default engine is now
# unconditionally offline faster-whisper, so google_cloud_stt only ever
# runs for a user who deliberately picked their OWN service-account JSON in
# Advanced > Backend. Paying grpc/protobuf/google-cloud's real install
# weight (and keeping it current on every source install) for a backend
# most users never touch no longer earns its cost. core/optional_deps.py's
# on-demand install (google-cloud-speech + google-cloud-storage together,
# so the cheaper GCS batch mode works without a second install) is now the
# ONLY install path, matching what docs/CLOUD_STT_GOOGLE.md's "Testing the
# connection" section already told users ("not bundled, to keep the base
# install small") before requirements.txt caught up to it.

# --- Notes -----------------------------------------------------------
# * tkinter ships with the Windows Python installer. On Linux install
#   python3-tk via the package manager. On macOS use the python.org build.
# * GPU support: the NVIDIA driver alone is not enough -- CTranslate2 4.x
#   also needs cuBLAS for CUDA 12 (4.6.3+ needs nothing else; older builds
#   also needed cuDNN). core/hardware.py finds it on the system path, in a
#   CUDA Toolkit, in a CUDA PyTorch, or from NVIDIA's pip wheel:
#       pip install nvidia-cublas-cu12
#   which the app's Advanced > Re-detect hardware > "Install GPU support"
#   button installs on demand (core/optional_deps.py "cuda_runtime").
# * darkdetect is optional and only used on macOS/Linux ("System" theme); Windows reads its own setting.
# * For dev / test deps see pyproject.toml [project.optional-dependencies.dev].
